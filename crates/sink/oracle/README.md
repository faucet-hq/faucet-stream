Oracle Database **sink** for the [faucet-stream](https://github.com/faucet-hq/faucet-stream) ecosystem. Writes pages with array DML, supports keyed `upsert` / `delete` through `MERGE`, atomic `overwrite`, exactly-once delivery, schema-drift evolution and table auto-creation. Built on the [`oracle`](https://crates.io/crates/oracle) driver (ODPI-C).

> **Runtime requirement:** Oracle Instant Client must be installed where ODPI-C can load it — see [`faucet-common-oracle`](https://crates.io/crates/faucet-common-oracle#runtime-requirement-oracle-instant-client).

## Highlights

- **Array DML** — one `INSERT … VALUES (:1, …)` executed for `batch_size` rows per round trip; a page commits in one transaction.
- **Exact binds** — values are bound per destination column type: 38-digit `NUMBER`s stay exact, ISO timestamps land in `DATE`/`TIMESTAMP[ WITH TIME ZONE]`, base64 in `RAW`/`BLOB`, ISO durations in `INTERVAL`s, objects/arrays as JSON text in `CLOB`/`JSON`.
- **Per-row failures** — rows the server rejects (value too large, constraint violation) or that cannot be encoded come back individually for DLQ routing; the rest of the page commits.
- **Write modes** — `append`, `upsert`, `delete` (keyed `MERGE` / `DELETE`), `overwrite`.
- **Exactly-once** — a `_faucet_commit_token` watermark committed with the data.
- **Schema drift** — add columns, widen integers to decimals, relax `NOT NULL`.

## Configuration

Connection fields are documented in [`faucet-common-oracle`](https://crates.io/crates/faucet-common-oracle#connection-settings).

| Field | Default | Description |
|---|---|---|
| `table` | — | Target, optionally owner-qualified (`APP.EVENTS`). |
| `column_mapping` | `{ type: auto_columns }` | `auto_columns` (keys → same-named columns; `on_unknown_field: warn \| drop \| error`) or `{ type: json_column, column: DATA }`. |
| `identifier_case` | `preserve` | `preserve` uses names as written (quoted, case-sensitive); `upper` upper-cases table, record keys, `key` and the JSON column — matching tables created with unquoted names. |
| `batch_size` | `1000` | Rows per array-DML execution (`0` = whole page). |
| `max_connections` | `5` | Pooled sessions. |
| `statement_timeout_secs` | `300` | Per-round-trip call timeout (`0` disables). |
| `create_table` | `true` | Create a missing table (see below). |
| `write_mode` | `append` | `append` / `upsert` / `delete` / `overwrite`. |
| `key` | — | Key columns for `upsert` / `delete`. |
| `delete_marker` | — | `{ field, values }`: `upsert` rows matching it become deletes. |

```yaml
sink:
  type: oracle
  config:
    host: db.example.com
    service_name: ORCLPDB1
    username: app
    password: ${secret:ORACLE_PASSWORD}
    table: APP.ORDERS
    identifier_case: upper
    write_mode: upsert
    key: [id]
    delete_marker: { field: __op, values: ["d"] }
```

### Table creation

With `create_table: true` a missing table is created from the first page: integers `NUMBER(19)`, doubles `BINARY_DOUBLE`, booleans `NUMBER(1)`, strings/objects/arrays `CLOB`, all nullable; key columns become `VARCHAR2(1000 CHAR)` (text) under a `PRIMARY KEY`. `json_column` mode creates `("ID" NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY, <column> CLOB)` up front. With `create_table: false` a missing table is a typed error.

Oracle stores `''` as `NULL`; an empty string is written as `NULL`.

## Write modes (upsert / delete)

`write_mode: upsert` / `delete` require `auto_columns` and a non-empty `key`. Each page is partitioned by the shared planner (last write wins per key; rows missing a key are rejected), then applied in one transaction with array-bound `MERGE INTO … USING (SELECT :1 AS … FROM DUAL) … WHEN MATCHED THEN UPDATE … WHEN NOT MATCHED THEN INSERT` and `DELETE … WHERE key = :n`. Only the columns present in the page are written. Pair with the `cdc_unwrap` transform to mirror a CDC source.

## Overwrite (`write_mode: overwrite`)

The run writes into `{table}__faucet_ovw`, created as `CREATE TABLE … AS SELECT * FROM target WHERE 1 = 0`. Only after a fully successful run is the target replaced, in one transaction (`DELETE` + `INSERT … SELECT` over the target's insertable columns), so readers see the old rows until the commit and a failure leaves them untouched; staging is then dropped. On a first run (no target) staging is created from the first page and renamed into place. The target keeps its constraints, indexes and grants.

## Exactly-once delivery

`write_batch_idempotent` writes the page and upserts `(scope, token)` into `_faucet_commit_token` (created beside the target, `scope VARCHAR2(1000 CHAR) PRIMARY KEY, token CLOB`) in the same transaction; `last_committed_token` reads it back. Composes with `write_mode: upsert`. Requires the CLI's exactly-once gate (a replayable source, durable state, no DLQ).

## Schema evolution

`current_schema()` reads `ALL_TAB_COLS` (`NUMBER(p,0)` → integer, `NUMBER(1,0)` → boolean-or-integer, other numerics → number, everything else → string). `evolve_schema` adds columns (`ALTER TABLE … ADD`), widens integer columns to `NUMBER`, and relaxes `NOT NULL`; each step is idempotent. Oracle cannot change a text column's type in place, so other widenings are reported as errors.

## Dead-letter queue

In `append` / `overwrite` mode, `write_batch_partial` executes array DML in batch-error mode: rows the server rejects, and rows whose values cannot be encoded for their column, are returned as per-row errors while the rest commit. In `upsert` / `delete` mode, rows missing a key are returned as per-row errors and the rest of the page is applied atomically. Connection-level failures fail the page.

## Preflight

`faucet doctor` checks the connection and whether the table exists (or will be created).

## Library usage

```rust,no_run
use faucet_core::Sink;
use faucet_sink_oracle::{OracleConnectionConfig, OracleSink, OracleSinkConfig};
use serde_json::json;

# async fn run() -> Result<(), faucet_core::FaucetError> {
let conn = OracleConnectionConfig::new("localhost", 1521, "FREEPDB1", "app", "secret");
let sink = OracleSink::new(OracleSinkConfig::new(conn, "EVENTS")).await?;
sink.write_batch(&[json!({"ID": 1, "NAME": "a"})]).await?;
# Ok(())
# }
```
