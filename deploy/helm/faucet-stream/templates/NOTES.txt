{{- if include "faucet-stream.serveSingleWithVolume" . }}
{{- if eq (include "faucet-stream.serveStrategy" . | fromYaml).type "Recreate" }}

Upgrades: one replica with a volume, so the Deployment uses the Recreate
strategy: the old pod stops before the new one starts (a short outage), and
a run in flight at that moment is marked failed. For no downtime, use
serve.history.backend=postgres without a volume, or run two replicas.
{{- else }}

WARNING: serve.strategy overrides Recreate for a single replica with a volume.
On a ReadWriteOnce disk an upgrade can hang (the new pod cannot attach the
volume while the old pod holds it), and two servers briefly share one SQLite
history file.
{{- end }}
{{- end }}

{{- if and .Values.serve.templatesSync.enabled (not (include "faucet-stream.durableHistory" .)) }}

WARNING: serve.templatesSync is on with a run history that does not survive a
restart (serve.history.backend={{ .Values.serve.history.backend }}{{ if eq .Values.serve.history.backend "sqlite" }} without serve.persistence{{ end }}). Synced
templates, their versions and launches live in the run history, so every pod
restart starts the registry from scratch (each template re-registers as
version 1 and `stable` follows only the sidecars again). Use sqlite (with
serve.persistence) or postgres to keep them.
{{- end }}
