# Metrics the code emits that no dashboard in observability/grafana/ shows.
#
# One `<metric>: <reason>` per line. `cli/tests/observability_artifacts.rs`
# fails when an emitted metric is on no dashboard and not listed here, and
# when a listed metric is charted or no longer emitted. Chart a metric unless
# it genuinely has no place on a dashboard.
faucet_notifications_pending: a gauge of batches waiting in the background queue; read it with the dropped counter (reason="queue_full"/"deadline") already charted
faucet_serve_clock_offset_seconds: a per-replica diagnostic for timestamps and timeouts (leases use the database clock); alerted on by FaucetServeClockSkew and shown per member on /readyz
faucet_serve_runs_lost_ownership_total: a rare failover event (a replica found its claimed run owned by a peer before starting it); counted for investigation, nothing to trend
faucet_serve_shard_coordinations_total: one increment per sharded run split; the outcome label is for investigating a lost or cancelled split, not for trending
faucet_serve_lease_renewal_timeouts_total: a rare event (a lease renewal or lost-lease check the history did not answer in time); alerted on by FaucetServeLeaseRenewalTimeouts, and faucet_serve_history_unreachable is charted
faucet_serve_lease_upkeep_skipped_total: a rare event (a lease tick found the previous tick's upkeep still running); alerted on by FaucetServeLeaseUpkeepBehind
faucet_serve_history_call_timeouts_total: a bounded history call of the lease upkeep that was cut off; read with the two lease alerts, nothing to trend
faucet_feed_store_moved: a per-feed 0/1 gauge for a misconfiguration (its events are in another feed store); alerted on by FaucetFeedStoreMoved and shown as the feed's status and on /readyz
faucet_feed_maintenance_behind: a per-feed 0/1 gauge (retention ran out of time); alerted on by FaucetFeedMaintenanceBehind, read with faucet_feed_trimmed_events_total
faucet_serve_schedule_compute_errors_total: a rare event (the cron library could not compute a schedule's next tick); the schedule's healthy gauge drops to 0, which FaucetServeScheduleUnhealthy alerts on
faucet_serve_tzdata_mixed: 1 only while a rolling upgrade spans two tzdata releases; alerted on by FaucetServeTzdataMixed
faucet_serve_history_unparseable_timestamps_total: a stored run-history timestamp that did not parse was read; a damaged row, repaired by hand, nothing to trend
